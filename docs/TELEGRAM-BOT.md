## Статус: РАБОТАЕТ, хостинг — GitHub Actions (24.09.2026)

- Бот: **@rudoctors_moderation_bot** (создан через @BotFather от Telegram-аккаунта
  `new` = balkandunav; админ-чат id 8953219173).
- Хостинг: **GitHub Actions** (`.github/workflows/telegram-moderation.yml`), публичный
  репозиторий = бесплатно, ничего держать запущенным не нужно.
  - `issues: opened/labeled` — мгновенная отправка новой заявки в чат (секунды);
  - `schedule: */5` + `push` + `workflow_dispatch` — обработка команд модерации.
    ⚠️ GitHub сильно задерживает/троттлит cron: обработка команды может занять от
    минут до часов. Если надо срочно — Actions → Telegram moderation → **Run workflow**
    (или запустить локально `npm run tg:bot` — см. ниже).
- Секреты Actions: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `BOT_GITHUB_TOKEN`
  (установлены через `gh secret set`). Локальный `site/.env` оставлен для ручного запуска.
- **Кнопки — URL, не callback:** «✅ Опубликовать» открывает чат с ботом с предзаполненной
  командой `/ok <N>` — нажми кнопку, затем «Отправить» в Telegram. Callback-кнопки не
  используются сознательно: Telegram **теряет** callback-нажатия, если бот не слушает в
  момент нажатия (проверено E2E), а обычные сообщения хранятся до 24 ч и забираются
  cron'ом.
- **E2E 24.09.2026:** заявка #4 → мгновенное уведомление → команда `ok 4` → заявка
  закрыта, JSON закоммичен, деплой Pages поднялся автоматически, ответ бота в чате.
  Тестовая карточка удалена. (Ранее также проверено: callback-режим локального бота,
  issues #1/#2.)
- **НЕ запускать `npm run tg:bot` локально одновременно с Actions** — два потребителя
  getUpdates конфликтуют (409, разделение апдейтов). Локальный запуск — только на время
  отладки и при отключённом workflow.

## Мгновенная обработка (опционально, локально)

Локальный `npm run tg:bot` можно держать запущенным ПАРАЛЛЕЛЬНО с Actions — апдейты
Telegram разделяются между потребителями, обработчики идемпотентны (закрытые issues
не трогаются второй раз). 409 в логе Actions при живом локальном боте — норма.
Локальный бот обрабатывает команды мгновенно; Actions — бэкстоп, когда ПК выключен.
Чтобы вернуть мгновенные callback-кнопки навсегда — нужен always-on long polling
(VPS: доступ к 84.247.170.107 отозван, восстановить через панель Contabo; либо
webhook-хостинг, напр. Cloudflare Workers).

## Как это работает

```text
Форма /add-doctor/
  → открывает чат @rudoctors_moderation_bot с уже вписанной заявкой
  → посетитель жмёт «Отправить» (Telegram) — всё, GitHub не нужен
  → бот (Actions/local) создаёт GitHub Issue (label doctor-request)
  → бот присылает карточку владельцу с URL-кнопками ✅/❌
      (кнопка открывает чат с командой «/ok N» — жать «Отправить»)
  → «ok N» → бот коммитит src/data/doctors/<slug>.json и закрывает issue
  → GitHub CI пересобирает сайт (~2–3 мин) → врач появляется в каталоге
  → «no N» → issue закрывается с комментарием «отклонено»
```

- Сообщения от НЕ-админов, начинающиеся с маркера формы («🩺 Заявка для каталога
  Rudoctors»), бот превращает в Issue и пересылает владельцу; посетителю уходит
  «Заявка принята». Команды `ok N`/`no N` принимаются ТОЛЬКО от админ-чата.
- GitHub Issue остаётся очередью и публичным следом заявки (консент-текст формы
  и политика конфиденциальности это отражают). Схему карточки бот собирает ту же,
  что и `/admin/` (`src/lib/types.ts`, `validateDoctor` в `src/lib/doctors.ts`).
- Подтверждение посетителю и создание Issue происходят в момент очередного запуска
  воркфлоу (push/cron/dispatch) или при живом локальном боте — обычно секунды.

Дополнительно бот:

- свободный текст специальности маппит на ключ из `src/data/specialties.json`
  (точное/частичное совпадение, иначе — транслит в новый ключ);
- раскладывает «Контакт» по полям: `@handle`/t.me → `contacts.telegram`,
  email → `contacts.email`, телефон → `contacts.phone`, нераспознанное → в bio;
- помечает отправленные заявки меткой `tg-sent`, чтобы не слать повторно.

## Настройка (один раз)

1. **Создать бота:** в Telegram у @BotFather → `/newbot` → получить токен
   вида `123456:AA…`.
2. **Узнать свой chat_id:** написать созданному боту `/start` при запущенном
   `npm run tg:bot` — он ответит и подскажет `chat_id`. (Либо временно
   запустить `npm run tg:bot` без настройки — в логе будет подсказка.)
3. **GitHub PAT:** создать fine-grained PAT (Settings → Developer settings →
   Fine-grained tokens) только на репозиторий `rudoctors/rudoctors.github.io`
   с правами **Contents: Read and write** и **Issues: Read and write**.
4. **Заполнить `site/.env`** по образцу `site/.env.example`:

   ```env
   TELEGRAM_BOT_TOKEN=123456:AA…
   TELEGRAM_ADMIN_CHAT_ID=123456789
   GITHUB_TOKEN=github_pat_…
   GITHUB_REPO=rudoctors/rudoctors.github.io
   ```

5. **Проверить и запустить:**

   ```powershell
   npm run tg:bot -- --check     # конфиг валиден?
   npm run tg:bot                # long polling (окно/терминал держать открытым)
   ```

`.env` в `.gitignore` — не коммитить и не переносить в память/PAIOS.

## Ограничения

- Бот работает, пока запущен скрипт. Кнопки, нажатые при выключенном боте,
  Telegram хранит ~24 часа и отдаст при следующем запуске; новые заявки
  уйдут в чат только после запуска. Если нужен always-on — скрипт можно
  поднять на любом бесплатном хосте без изменений кода.
- При «✅» бот коммитит прямо в `main` (как и `/admin/`) — публикация
  необратима на уровне бота; откат — через `/admin/` (hidden) или git.
- Повторный нажатый «✅» на обработанной заявке безопасен: бот ответит
  «уже обработана».
